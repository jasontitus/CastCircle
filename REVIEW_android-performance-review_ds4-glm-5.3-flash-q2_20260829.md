- [medium] android/app/src/main/kotlin/com/tiltastech/lineguide/AndroidSttPlugin.kt:380-385 — per-chunk ByteArray allocation in the capture loop — every 100 ms a fresh `ByteArray(n*2)` is allocated solely to feed the encoder, while the same data is already available as the ShortArray `pcm`; at 16 kHz mono that is ~3.2 KB garbage per chunk, ~32 KB/s, ~1.9 MB/min of allocation churn on the capture thread that only stresses the GC and adds no capability — reuse a single preallocated `ByteArray(CHUNK_SAMPLES*2)` member and write into it (clearing length when `n < CHUNK_SAMPLES`).
- [medium] android/app/src/main/kotlin/com/tiltastech/lineguide/AndroidSttPlugin.kt:386-392 — two MethodChannel round-trips per 100 ms chunk — `onLevel` and `onPcm` are posted as separate `invokeMethod` calls on the main handler for every chunk; each crossing pays channel serialization + a Dart microtask, and the PCM payload (~3.2 KB) is copied per message; at 10 messages/s × 2 the platform channel becomes the hottest path in the app and the main-thread handler queue can back up if Dart stalls — coalesce into one `invokeMethod("onPcm", mapOf("bytes" to bytes, "level" to level))` so one crossing carries both values.
- [low] android/app/src/main/kotlin/com/tiltastech/lineguide/AndroidSttPlugin.kt:368-369 — busy-spin when AudioRecord returns 0 — `if (n <= 0) continue` re-reads immediately with no sleep/backoff; if the recorder briefly yields no data (state race, buffer underrun) the loop spins the capture thread at full CPU until data resumes — add a small `Thread.sleep(5)` (or check `record.recordingState`) before continuing.
- [low] android/app/src/main/kotlin/com/tiltastech/lineguide/AndroidSttPlugin.kt:442-455 — a new Thread allocated per stopRecording call — each stop spawns a short-lived `Thread("RehearsalCaptureStop")` just to join(3000) and post a result; frequent start/stop cycles (rehearsal takes) allocate a thread per stop instead of reusing a pool — reuse a single-thread executor or the existing mainHandler with a delayed post.
- [low] android/app/src/main/kotlin/com/tiltastech/lineguide/AndroidSttPlugin.kt:480-483 — same per-call thread allocation in releaseRecorderAsync — every `stopListening`/detach that races an active capture allocates another throwaway `Thread("RehearsalCaptureRelease")`; same class as the previous finding, same fix (shared executor).
