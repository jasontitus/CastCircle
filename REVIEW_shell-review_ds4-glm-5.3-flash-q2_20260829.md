- [medium] scripts/deploy.sh:24 — `process launch` failure is silenced by `|| true` and its output is discarded, so a launch failure (e.g. app crashed on startup, device policy) is reported as "✓ deployed + launched" — drop `|| true` (or capture the exit status) and report launch failure distinctly.

- [low] scripts/deploy.sh:9 — `DEVICE` is hardcoded to a specific device UDID; on any other machine the install loop always fails after 6 attempts with a misleading "device locked/busy?" hint — read the device id from an env/argument with this value as default, or fail early with a clear "device not configured" message.
- [low] scripts/deploy.sh:11 — `cd "$(dirname "$0")/.."` assumes `$0` is a readable path; when invoked via a relative path from a different cwd or through a symlink, `..` may not be the repo root and the subsequent `build/ios/...` relative path silently misses — use `cd "$(dirname "$(readlink -f "$0" 2>/dev/null || echo "$0")")/.."` or resolve the repo root via `git rev-parse --show-toplevel`.
